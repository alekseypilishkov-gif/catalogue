## Уточнение задач

Перед выполнением любой задачи задай уточняющие вопросы.

Не начинай изменять файлы, Figma-макеты или внешние данные, пока пользователь явно не подтвердит понимание задачи.

Исключение: если пользователь явно пишет, что уточнения не нужны или просит выполнить действие сразу.

## Аудит цветов компонентов Figma

Когда пользователь предоставляет ссылку на конкретный узел Figma и просит проверить цвета, соответствие цветов, semantic variables или провести аналогичный аудит, выполняй следующие инструкции.

### Порядок работы

1. Извлеки из ссылки:
   - `fileKey`;
   - `node-id`.

2. Сразу начинай аудит. Для этой задачи дополнительные уточнения и повторное подтверждение не требуются.

3. Используй Figma только в режиме чтения.

4. Не изменяй:
   - компоненты и варианты;
   - fills и strokes;
   - переменные и коллекции;
   - структуру файла;
   - названия слоёв;
   - любые другие данные Figma.

5. Проверь весь переданный узел, включая:
   - вложенные компоненты;
   - Component Set;
   - все варианты и состояния;
   - адаптивные размеры;
   - экземпляры вложенных компонентов;
   - fills и strokes;
   - цвета текста, иконок, фонов, границ и разделителей.

### Что проверять

Выявляй:

1. Цвета, заданные напрямую без переменных.
2. Primitive- или legacy-переменные, используемые вместо `semantic/*`.
3. Семантически неверные привязки, даже если их текущие RGB-значения совпадают.
4. Несогласованность между состояниями:
   - normal;
   - hover;
   - active/pressed/clicked;
   - focus;
   - disabled.
5. Различия цветовых привязок между размерами одного компонента.
6. Различия между одинаковыми компонентами в разных Component Set.
7. Отсутствующие semantic tokens, для которых нет подходящей существующей переменной.
8. Технические fills/strokes Figma, которые не влияют на визуальный цвет интерфейса.
9. Игнорируй служебные цвета Figma

### Правила сопоставления

- Предпочитай существующие переменные `semantic/*`.
- Не предлагай primitive-переменную как итоговую привязку.
- Не считай привязку корректной только потому, что её текущее значение визуально совпадает с нужным цветом.
- Учитывай назначение слоя и компонента:
  - фон кнопки;
  - текст кнопки;
  - иконка;
  - граница;
  - фон страницы;
  - фон карточки;
  - фон таблицы;
  - hover-состояние;
  - disabled-состояние.
- Если точного semantic token нет, явно укажи пробел дизайн-системы.
- Не придумывай существование переменной, которой нет в файле.
- Отделяй реальные интерфейсные цвета от:
  - фиолетовых обводок Component Set;
  - технических заливок контейнеров иконок;
  - служебного оформления секций Figma.

### Формат результата

Сначала укажи:

- название и ID проверенного узла;
- количество найденных компонентов и Component Set;
- подтверждение, что файл не изменялся.

Затем представь несоответствия таблицей:

| Компонент / вариант | Слой и свойство | Сейчас | Предполагается | Уверенность | Обоснование |
|---|---|---|---|---|---|

После таблицы отдельно перечисли:

1. Однозначные исправления.
2. Предположительные исправления.
3. Отсутствующие semantic tokens.
4. Корректные системные привязки.
5. Служебные цвета Figma, которые менять не нужно.

Заверши кратким выводом с приоритетом исправлений.

### Ограничение

Этот сценарий предназначен только для аудита.

Не вноси исправления, даже если они очевидны. Изменения разрешены только после отдельной явной команды пользователя.
